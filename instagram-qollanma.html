Ulash tartibi

Tartib muhim: oldingi qadamsiz keyingisi ishlamaydi. Belgilar faqat sizning brauzeringizda saqlanadi.

0 / 8 bajarildi

  1. Server tayyor

    Tunnel http2 bilan ulangan va Mac uxlamaydi. Pastdagi "Server ishlayaptimi" buyrug'ini ishga tushiring: 4 ta protocol=http2 ulanish va api 200 chiqishi kerak.

  2. Instagram akkaunt professional va sahifaga bog'langan

    Biznes yoki Creator akkaunt. Unga Facebook sahifa bog'langan bo'lishi kerak: Direct xabarlar shu sahifa orqali keladi.

  3. App Review o'tmaguncha: akkaunt tester bo'lsin

    • developers.facebook.com → NajotSoft CRM → Роли в приложении → Добавить людей → Тестировщик Instagram.
    • Mijoz Instagram'da qabul qiladi: Settings and activity → Website permissions → Apps and websites → Tester invites → Accept.
    • Biz sinaganda xabar yozuvchi ham tester edi. Testersiz mijozdan xabar kelishi sinalmagan.

  4. Ilovada Messenger sценарийsi bor

    Bir marta qilinadi, 2026-11-16 da qilingan. developers.facebook.com → NajotSoft CRM → Сценарии использования ro'yxatida «Взаимодействие с клиентами в Messenger» turishi kerak, unda pages_manage_metadata va pages_messaging «Готово к тестированию» holatida.

  5. Panelda ulash

    • Token bilan ulash (sinalgan): system user token, 7 ta ruxsat bilan: instagram_basic, instagram_manage_messages, instagram_manage_comments, pages_show_list, pages_manage_metadata, pages_messaging, business_management. Token ilova admini bo'lgan Facebook akkaunt bilan yaratiladi.
    • Instagram orqali ulash (OAuth) mijozlar uchun asosiy yo'l, lekin hali sinalmagan. Ishlatishdan oldin Facebook Login for Business → Конфигурации'da yuqoridagi 3 ta pages_* ruxsat konfiguratsiyada borligini tekshiring.
    • Ulangandan keyin panelda "Direct xabarlar kelmaydi" ogohlantirishi chiqmasligi kerak.

  6. Sahifada asosiy ilova = NajotSoft CRM

    facebook.com'da sahifaga o'tish → Настройки → Настройка Страницы → «Маршрутизация переписки в Instagram» → «Приложение для маршрутизации по умолчанию» → NajotSoft CRM. Buni sahifa egasi qiladi va u faqat 5-qadamdan keyin ro'yxatda chiqadi.

  7. Instagram'da xabarlarga ruxsat

    Agar menyuda bo'lsa: Settings and activity → Messages and story replies → Message controls → Connected tools → Allow access to messages yoqilgan. Bizning sinovda bu bo'lim topilmadi, lekin xabarlar baribir keldi.

  8. To'liq sinov

    • Tester akkauntdan Direct xabar yozing: panelda 1–2 soniyada chiqadi.
    • Paneldan javob yozing: Instagram'da ko'rinadi.
    • Paneldan rasm va PDF, Instagram'dan rasm va ovoz yuboring.

Panelda "Failed to fetch", ulash tugmasi hech narsa qilmaydi

Kodda tuzatildi · 845af0a
Failed to fetch
Sabab
Cloudflare tunnel QUIC (UDP) orqali ulangan edi, bu tarmoqda u har necha daqiqada failed to dial to edge with quic: timeout bilan uzilardi. Brauzer so'rovi serverga yetmasdi, Meta webhook'lari ham yo'qolardi. 5 kunda 4945 ta tunnel xatosi bo'lgan.
Tekshirish
Bazada channel.reconnected yozuvi yo'q va api logida so'rov ko'rinmaydi: demak so'rov serverga umuman yetmagan. Tunnel logida ERR qatorlari ko'p bo'ladi.
Yechim
docker-compose.tunnel.yml da cloudflared --protocol http2 (TCP) bilan ishga tushadi. Mac uxlamasin: Energiya sozlamalari yoki caffeinate -dis.
Eslatma
Yangi kod o'rnatilganda (api qayta ishga tushganda) 5–10 soniya davomida ham "Failed to fetch" chiqadi. Bu vaqtinchalik: biroz kutib qayta urining.

Izohlar keladi, Direct xabarlar kelmaydi

Meta sozlamasi
Direct xabarlar kelmaydi (izohlar keladi): Instagram'ga bog'langan Facebook sahifasiga ruxsat yo'q
Sabab
Meta Direct xabarlarni akkauntga bog'langan Facebook sahifa orqali yuboradi. Tokenda pages_* ruxsatlari bo'lmagani uchun ilova sahifaga obuna bo'lolmadi. Akkaunt obunasi bor edi, shuning uchun izohlar kelardi.
Tekshirish
  • api logida: Direct messages will not arrive (page=not shared).
  • Tokenni Access Token Debugger'ga joylang: Scopes ro'yxatida pages_show_list, pages_manage_metadata, pages_messaging bo'lishi kerak.
Yechim
7 ta ruxsatli yangi token yarating (avval Messenger sценарийsi va admin akkaunt) va panelda Token bilan ulash'ni qayta bosing. Kanal o'chmaydi, faqat tokeni almashadi va ilova sahifaga obuna bo'ladi.

Diagnostika

Tekshirish buyruqlari

Mac terminalida, loyiha papkasida (~/Projects/sotuvchi-ai) ishga tushiriladi. Hech biri token yoki parolni ekranga chiqarmaydi.

Server ishlayaptimi. Konteynerlar holati, tunnel protokoli va api javobi.

docker compose -p sotuvchi-tunnel ps
docker logs sotuvchi-tunnel-tunnel-1 2>&1 | grep -E "Registered|ERR" | tail -6
curl -s -o /dev/null -w 'api %{http_code}\n' https://api.najotsoft.uz/health

Meta nima yuboryapti. Webhook'lar, fayl yuklab olishlar, ulash ogohlantirishlari.

docker logs --since 1h sotuvchi-tunnel-api-1 2>&1 \
  | grep -E "instagram webhook|file link|Direct messages will not arrive|Instagram token|signature" \
  | tail -20

Nega yuborilmadi. Worker'ning chiquvchi xabar xatolari.

docker logs --since 1h sotuvchi-tunnel-worker-1 2>&1 | grep -iE "outbound|failed" | tail -10

Bazada nima bor. Oxirgi Instagram xabarlari va kanal ulanishlari.

docker compose -p sotuvchi-tunnel exec -T postgres psql -U sotuvchi -d sotuvchi -c "
select m.direction, m.created_at, m.status, left(m.text, 40) as text
from messages m join channels c on c.id = m.channel_id
where c.type = 'instagram' order by m.created_at desc limit 10;"
docker compose -p sotuvchi-tunnel exec -T postgres psql -U sotuvchi -d sotuvchi -c "
select action, created_at from audit_log where action like 'channel.%' order by created_at desc limit 5;"

Yangi kodni o'rnatish. api va worker'ni qayta yig'adi. 5–10 soniya panel javob bermaydi.

docker compose -f docker-compose.prod.yml -f docker-compose.tunnel.yml \
  --env-file .env --env-file .env.tunnel up -d --build api worker
